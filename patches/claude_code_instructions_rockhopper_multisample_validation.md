# Claude Code向け指示書: Rockhopperの複数サンプル・複数条件検証(Phase 6e追加調査)

## 位置づけ・目的

Phase 6eの単一サンプルでの検証結果(`claude/phase6e_operon_prediction_investigation.md`)で、
Nif複合体・Mcr活性化複合体クラスタは正しくオペロンとして検出できたが、
Mtp複合体(MA_4164/MtpA, MA_4165/MtpC, gap 70bp)は10万/300万/835万リードの
いずれでも検出されなかった。これは実装判断を左右する重要な未解決点であり、
引き続き**調査指示書**として、実装(`analysis/operon_bridge.py`相当)には進まず
調査を継続する。

## 仮説: 条件依存の発現量不足ではないか

RNA-seqベースのオペロン予測は、**そのサンプル・条件下で実際に転写されている
かどうか**に依存する。Rockhopperが「オペロン構造としてグループ化できない」
としても、それは「ゲノム上オペロンではない」ことの証明にはならず、単に
「そのサンプルでは発現が低すぎた/条件的に転写されていなかった」だけの
可能性がある。

MtpA/MtpC(MA_4164/MA_4165)は"methylotrophic"系のメチル基転移酵素複合体で
ある可能性が高く、これは*M. acetivorans*の増殖基質(酢酸/メタノール/
トリメチルアミン/メチル化硫黄化合物)によって発現量が大きく変動する遺伝子群
の典型例。前回の検証で使ったサンプルがどの条件のものだったかを確認し、
もし基質条件がMtpの発現に不利なもの(例えば酢酸増殖)だった場合、
条件を変えて再検証する価値がある。

## 調査してほしいこと

### 1. 前回テストに使ったサンプルの条件を確認

前回どのGSE77738サンプル(アクセッション番号、増殖条件: acetate/methanol/
TMA/RNA half-life のどれか)を使ったのかを確認する。もし記録が残っていなければ、
使用したSRAランID(`SRP069835`配下)から遡って特定する。

### 2. 処理済みサマリファイルでMtp遺伝子の発現量を条件横断的に確認

Phase 6bで既にダウンロード済みのGEO処理済みファイル(XLSX、GSE77738の61
サンプル分・GSE64349の15サンプル分)を使い、**FASTQを新たにダウンロードせず**、
MA_4164・MA_4165の発現量(TPM/FPKM相当の列)を全サンプルで確認する。

```python
# 例(実際の列名・シート構成はダウンロード済みファイルに合わせて調整)
import pandas as pd

df = pd.read_excel("path/to/GSE77738_processed.xlsx")
mtp_rows = df[df["locus_tag"].isin(["MA_4164", "MA_4165"])]
print(mtp_rows)
```

- GSE77738内の条件別(acetate / methanol / TMA / RNA half-life)で
  MA_4164/MA_4165の発現量に有意な差があるか
- GSE64349(メチル化硫黄化合物条件、DMS/MMPA/MeSH)でも同様に確認
- 前回検証に使ったサンプルの発現量が、他条件と比べて低かったかどうか

これでMtp検出失敗が「発現条件の問題」なのか「Rockhopperの手法的限界」
なのかの見当がつく。

### 3. 発現量が高そうな条件のサンプルでRockhopper再実行

上記2の結果、Mtpの発現量が明確に高い条件のサンプルが見つかった場合、
そのサンプル(1〜2件で可)についてFASTQを取得し、前回と同じ手順で
Rockhopperを実行し、Mtp複合体がオペロンとして検出されるか確認する。

見つからなかった場合(全条件で発現量が低い、または差が無い)は、その旨を
報告し、無理にFASTQ取得・再実行はしなくてよい(前回同様ネットワークが遅い
場合は3段階のリード数サブサンプリングで様子を見る形で構わない)。

### 4. Nif/Mcrの正例側の頑健性も確認

Mtpの追加検証と合わせて、前回ポジティブだったNif複合体・Mcr活性化複合体
クラスタの検出が、**別のサンプル・条件でも再現するか**を1〜2件確認する。
1サンプルだけでの成功は偶然の可能性も排除できないため、複数サンプルでの
再現性を見ることが本調査の主目的の一つ。

### 5. コストの再評価

複数サンプルを扱う場合の実行時間・ディスク使用量を、前回の単一サンプル
(約10〜15分/サンプル、<1.5GB memory)の見積もりと比較して更新する。
特に、FASTQダウンロードがボトルネックになる場合(前回Cowork側で
約0.87MB/sしか出なかった件)、ローカル環境ではどの程度の速度が出るかも
記録してほしい。
