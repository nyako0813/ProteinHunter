# Claude Code向け指示書: Rockhopperオペロン予測 — デスクトップでのゼロからの環境構築・LK57サンプル検証(Phase 6e継続)

## 位置づけ・重要な前提

これは**調査指示書**です(実装指示書ではありません)。オペロン構造の直接
予測ツールRockhopperの調査(Phase 6e)の続きですが、**この調査は元々別の
マシン(ノートパソコン)で行われており、その作業成果(調査レポートの
markdownファイル、ダウンロード済みFASTQ、Rockhopper本体・実行環境)は
このマシン・このリポジトリには一切残っていません**。`git log`上は
`origin/main`に追いついていますが、これらの調査成果物はそもそも一度も
コミット・pushされていません(調査指示書という性質上、実装コードでは
ないため)。

したがって、以下は**このマシン上でゼロから環境構築し直す**ための、自己
完結した指示書です。前提となる調査結果は、この指示書の中に必要な分だけ
要約して埋め込んであります。

## これまでの調査の要約(このリポジトリには存在しない情報)

- このプロジェクトの核心課題: MA_4115(および他クエリ)の候補タンパク質
  ランキングにおいて、「同じオペロンの非隣接メンバー」を検出できていない
  (隣接遺伝子ペアのオペロン間隔閾値は`_gene_neighborhood_v2`で既に150bp
  閾値として実測・解決済み)。
- 候補ツールとしてRockhopper(ゲノム配列+RNA-seqリードから直接オペロン
  構造を予測するJavaツール、https://cs.wellesley.edu/~btjaden/Rockhopper/)
  を調査中。
- 既知の3複合体を検証用ベンチマークとして使っている:
  - Mcr活性化複合体クラスタ: MA_4546, MA_4547, MA_4548, MA_4549, MA_4550
    (隣接gap 2〜25bp)
  - Nif複合体: MA_3896(NifI1), MA_3897(NifI2), **MA_3898(nifD)**,
    **MA_3899(nifK)**(隣接gap 3〜28bp。**NifI1とnifKは非隣接**、これが
    まさに埋めたい穴。旧ドキュメント・旧指示書では3898/3899のnifD/nifK
    ラベルが逆になっていたが、実際の`genome.gff`とNCBI最新アノテーション
    で確認済みの正しいラベルは上記の通り)
  - Mtp複合体: MA_4164, MA_4165(gap 70bp)
- 前回(別マシンでの)検証結果: GSE77738由来のあるサンプルで100,000/
  3,000,000/8,350,000リードの3段階を試したところ、**Nif複合体・Mcr
  クラスタは正しく1つの転写単位として検出できた**が、**Mtp複合体は
  3段階すべてで検出されなかった**(個々の遺伝子の発現量自体は十分だった)。
- 上記の未検出が「Rockhopperの手法的限界」なのか「そのサンプルの増殖条件
  でMtpの発現が条件的に低かっただけ」なのかを切り分けるため、GSE77738の
  処理済みサマリファイルでMA_4164/MA_4165の発現量をサンプル横断的に確認
  したところ、**サンプル「LK57」(酢酸(acetate)増殖条件)がMtp発現量が
  最も高いサンプルの一つ**として特定された(前回マシンでの結果)。
- 前回マシンでLK57のFASTQダウンロードを開始したが、ネットワーク速度が
  遅く(~0.87MB/s)、1.5GB(全体の約33%)の時点で作業を中断した。

## Rockhopperの技術的な要注意点(前回判明分)

- ダウンロードページの静的URLが直接JARファイルを指さない場合がある。
  サイトのJavaScript実装を確認して実際のダウンロードリンクを特定する
  必要があった(前回はこの方法で解決)。
- Rockhopperは**GFF3ではなく、レガシーなNCBI `.ptt`/`.rnt`形式**を要求
  する。GenBankフラットファイル(`.gb`/`.gbk`)からBiopython
  (`Bio.SeqIO`)経由で`.ptt`/`.rnt`を生成する変換スクリプトが必要
  (前回は新規に書いた。このリポジトリには存在しないため、改めて書く
  必要がある)。
- 実行にはJavaが必要。sudo権限なしで動くポータブルJRE(前回使用)でも
  問題ない。

## 調査してほしいこと

### 1. 環境確認・下準備

```bash
java -version
find data -iname "*GSE77738*" -o -iname "*GSE64349*" -o -iname "*SRP069835*" -o -iname "*.ptt" -o -iname "*.rnt"
```

Java・既存データの有無を確認(このマシンでは無い可能性が高いが念のため)。

### 2. Rockhopper本体の取得

`https://cs.wellesley.edu/~btjaden/Rockhopper/` から取得を試み、404等で
失敗する場合はページのJavaScriptを確認して実際のダウンロードURLを特定する。

### 3. ゲノム入力データの変換

既存の候補生成パイプラインが使っているゲノムFASTA/GFF
(`data/input/genome.gff`相当)に対応するGenBankフラットファイルを
NCBI(Assembly GCF_000007345.1、*Methanosarcina acetivorans* C2A)から
取得し、Biopython経由で`.ptt`/`.rnt`形式に変換するスクリプトを書く。

### 4. LK57サンプルのFASTQ取得(部分でよい)

GSE77738(SRP069835)のLK57サンプル(酢酸増殖条件)のFASTQを、ENA経由の
HTTPS直接ダウンロードで取得する。ネットワークが遅い場合は、前回同様
無理に全量(1.8GB)を取得せず、部分データ(例えば1.5GB程度、または
リード数で100,000/3,000,000/8,350,000のいずれか)で構わない。もし途中で
中断された前回のダウンロードの再開ができるなら、それでもよい。

### 5. Rockhopper実行とMtp検出確認

genome(.ptt/.rnt) + LK57のリードでRockhopperを実行し、**Mtp複合体
(MA_4164/MA_4165)が1つの転写単位として検出されるか**を確認する。
これが今回の核心の問い。

あわせて、Nif複合体(MA_3896〜MA_3899、特にNifI1-nifKの非隣接ペア)・
Mcrクラスタについても、このLK57サンプルで検出が再現するかを確認する
(別サンプルでの結果の頑健性確認)。

### 6. コスト評価

このマシンでゼロから環境構築した場合の所要時間(Java/Rockhopper準備、
.ptt/.rnt変換スクリプト作成、FASTQ取得、Rockhopper実行それぞれ)を記録
する。前回マシンでの見積もり(1サンプルあたり実行時間10〜15分、
メモリ<1.5GB)と比較できる形で構わない。

## 成果物として欲しいもの

1. 環境構築の所要時間・つまずいた点(あれば)
2. LK57サンプルでのMtp複合体検出結果(検出できた/できなかった)
3. Nif複合体・Mcrクラスタの再現性確認結果
4. 「Mtp未検出の原因は条件依存の発現不足か、Rockhopperの手法的限界か」に
   ついての率直な所見(LK57で検出できれば前者が濃厚、できなければ後者の
   可能性が高まる)
5. このマシンでの環境構築コスト評価
